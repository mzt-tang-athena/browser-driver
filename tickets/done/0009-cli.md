## Spec

The driver needs a second client beside MCP. A thin CLI keeps the same
API and adds the tool humans, scripts, and shell agents already know.

1. One command per API operation: `run`, `status`, `events`, `approve`,
   `stop`, `observe`, `act`.
2. JSON output by default, so a shell agent can pipe it to `jq`.
3. `events --follow` long-polls for new step lines.
4. Exit codes that say what happened: done, paused, blocked, failed.
5. Config from flags or env: base URL and token.
6. No browser code in the CLI. It is a client of the service.
7. Installable as one binary entry, `browser-driver`.

## Acceptance

- [x] Every command runs against the service and prints JSON
- [x] `events --follow` shows steps as they happen
- [x] Exit codes match the run outcome
- [x] Docs show a full run from a shell
- [x] Tests use a stub server, not a browser

## Outcome

Done on 2026-10-29.

- Commands: `run`, `status`, `events`, `approve`, `stop`, `observe`, and
  `act`, each one call to the HTTP API. Every command prints JSON. `run`
  prints one object at the end; `events` prints one JSON line per event.
- `run` waits by default. It follows the event stream with an `after`
  cursor, so a quiet run does not make it re-read the whole stream.
  `--no-wait` returns the run id at once, and `--quiet` drops the progress
  lines that go to stderr.
- Exit codes: 0 done or running, 1 error, 2 paused or needs-human-input,
  3 blocked, 4 max-steps. `run` and `status` use them.
- Config: `--base-url` and `--token`, or `BROWSER_DRIVER_URL` and
  `BROWSER_DRIVER_TOKEN`. The token is required.
- The bin entry is `browser-driver` through `bin/browser-driver.mjs`,
  which runs the TypeScript CLI with `tsx`. `npm link` puts it on the
  path; that was checked with a temporary prefix.
- 16 tests run against a stub HTTP server. They cover every command, the
  cursor in `run`, the follow loop, all six exit codes, a service error,
  and missing config. No browser and no service code.
- A live check against the running service: a form run finished done with
  exit 0, approving a gate finished done, denying it finished blocked with
  exit 3, a cost cap of zero paused with exit 2, and observe, act, and
  stop worked on the paused run.
